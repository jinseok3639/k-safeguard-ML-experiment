# E2b — BiLSTM 코퍼스 스케일링 (부분 실행, 중단됨)

> 상태: `PARTIAL_INTERRUPTED`
>
> `e2-bilstm-30k` 실행을 tensify 학습 도중 의도적으로 중단했다. run 산출물(metrics.json 등)이
> 없으므로 이 문서가 유일한 기록이다.

## 왜 중단했나

이 실행은 abstention 없이 argmax 수치만 낸다. 그런데 실행 중에 돌린 E8이 abstention이
결정적이라는 것을 보여줬으므로, 남은 tensify 지점은 어차피 E8 조합으로 다시 재야 하는
값이었다. BiLSTM은 CPU에서 기법당 26~32분이 걸려 한계 효용 대비 비용이 맞지 않았다.

## 얻은 것 — BiLSTM은 코퍼스에 계속 반응한다

| 기법 | 8,000문장 (E2) | 30,000문장 (여기) |
|---|---|---|
| liaison | 음절exact 0.766 / 오변경 5.9% | **0.893 / 2.9%** |
| jongseong_cram | 0.667 / 12.7% | **0.738 / 2.0%** |
| tensify | 0.997 / 6.9% | 미측정 (중단) |

학습 시간: liaison 1,918초, jongseong_cram 1,586초 (6스레드 CPU). p95 지연 8.7~8.9ms.

## 의미

E1에서 **선형** 모델은 코퍼스를 500→100,000문장으로 200배 늘려도 곡선이 8천문장 부근에서
누웠다. BiLSTM은 8천→3만(4배)만으로 오변경이 절반 이하로 떨어진다.

즉 **아키텍처가 코퍼스 스케일링을 열어준다.** 고정 창(±4자) 모델은 문맥을 더 못 담으므로
데이터를 부어도 쓸 데가 없었고, 문장 전체를 읽는 모델이 되어서야 늘어난 어휘가 실제로
쓰이기 시작한다. E1의 "데이터로는 안 된다"는 결론이 왜 틀렸는지에 대한 두 번째 증거다.

## 해석 제한

- 두 지점(8천·3만)뿐이라 곡선이라 부르기 어렵다. 기울기만 확인한 수준이다.
- abstention 없는 argmax 수치다. E8과 직접 비교하면 안 된다.
- tensify는 측정하지 못했다.
- 단일 실행이며 run manifest가 없다 — 재현하려면 `python -m exp.run_e2_architecture
  --run-id <id> --corpus-size 30000 --architectures bilstm --skip-ablation` 를 다시 돌려야 한다.
