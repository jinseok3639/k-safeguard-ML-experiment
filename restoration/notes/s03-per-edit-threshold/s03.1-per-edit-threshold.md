# S03.1 편집 종류별 임계값 배분

- id: `s03.1-per-edit-threshold`
- 단계: `s03-per-edit-threshold`
- 비교 대상: `e11d-oracle-detector-20261014` (같은 합집합 모델, 공통 임계값)
- 실행 명령: `python -m restoration.exp.run_s03_edit_thresholds --run-id s03.1-per-edit-threshold --no-progress`

## 왜 돌리나
가설: 합집합 모델의 문제는 '확신도의 눈금이 편집 종류마다 다르다'는 것이다. 초성을 된소리에서 되돌리는
편집은 확신도가 0.999대로 높고, 받침을 떼어 내는 편집은 맞아도 확신도가 낮다. 한 줄로 자르면 낮은
쪽이 다 잘린다. 종류마다 선을 따로 그으면 benign 예산은 같게 두고 잘린 몫을 되찾을 수 있다.

임계값 정하는 규칙(실행 전 고정):
1. **편집 종류**는 추론 때도 알 수 있는 것으로 나눈다 — 모델 예측이 입력과 다른 슬롯: 초성만 / 모음만 /
   받침만 / 두 슬롯 이상. 기법 이름은 쓰지 않는다(실전 입력에 붙어 오지 않는다).
2. **예산**: benign dev(KOTOX 학습 분할 정상 문장 1,835개)에서 바뀌는 문장이 1% 이하(18개 이하).
   종류별로 따로가 아니라 **문장 단위 합계**로 센다 — 한 문장에서 두 종류가 바뀌어도 1개.
3. **배분(추천안, 탐욕 배분)**: 모든 종류의 임계값을 benign dev가 하나도 안 바뀌는 높이에서 시작한다.
   한 걸음마다 각 종류에 대해 '정상 문장이 하나 더 바뀌기 직전까지' 임계값을 내려 보고, **공격 dev**의
   CER 감소가 가장 많이 느는 종류 하나만 실제로 내린다(같은 확신도의 정상 문장이 여럿이면
   한 번에 여러 개를 쓰므로, 비교는 새로 쓴 정상 문장 하나당 늘어난 양으로 한다). 정상 문장에 한 번도
   나오지 않는 종류는 처음부터 바닥(임계값 0)이다. 예산(18개)을 다 쓰거나 늘어나는 종류가 없으면
   멈춘다.
4. **공격 dev**: 코퍼스의 평가 분할(학습에 안 쓴 20%, 해시 분할) 문장에서 기법 13개 × 강도 0.5·1.0으로
   우리 생성기가 만든 난독화 문장. 505 시드와 KOTOX test는 임계값을 고르는 데 쓰지 않는다.
5. 모델 시드 3개마다 따로 정한다. 같은 규칙으로 예산 0.5%·2%도 계산해 곡선을 남기되, 판정은 1%로 한다.

비교군(같은 모델·같은 예산):
- **공통 임계값**: S02 방식 그대로(재현 확인용 — S02 수치와 같아야 한다).
- **균등 배분**: 종류마다 benign dev 4문장(0.25%)씩. 합계 1% 이하.
- **참고선**: 임계값 없음(전부 적용), 단일 기법 모델(S02.4 수치, 받침 크래밍 +12.08%p).

판정 기준(505 시드는 합집합 모델 시드 3개 평균, 기법 단위 강도 0.5·1.0 평균):
| 질문 | 기준 |
|---|---|
| 받침 크래밍이 돌아오나? | jongseong_cram CER 감소 ≥ 6%p (단일 모델 12.08의 절반) |
| 다른 기법을 희생하지 않나? | 13기법 평균 CER 감소가 공통 임계값 이상, tensify 감소 폭 ≤ 1%p |
| 남의 데이터에서도 나아지나? | KOTOX test 슬롯 가역 쌍 CER 감소 ≥ 2%p (S02: +0.67%p) |
| benign 예산이 test에서도 지켜지나? | benign test(KOTOX test 정상 + 시드 benign) 변형률 ≤ 1% |

예상(실행 전, Claude):
- 받침 크래밍은 기준(6%p)을 넘을 것이다. 받침 편집은 benign 문장에서 잘 안 나오는 종류라 예산을 적게
  쓰고도 크게 내릴 수 있다.
- tensify는 거의 그대로(1%p 안쪽)일 것이다 — 초성 종류는 이미 높은 확신도에서 잘렸다.
- KOTOX 슬롯 가역 쌍은 기준(2%p)에 못 미칠 것이다. 임계값을 전부 꺼도 +2.07%p였으므로 보정으로 얻을 수
  있는 위쪽 한계가 그 근처다. 외부 데이터 문제는 생성기 쪽(S04)이라고 본다.
- benign test 변형률은 1%를 조금 넘을 수 있다. 종류마다 선을 따로 고르면 dev에 더 맞춰지기 때문이다.
- 탐욕 배분이 균등 배분보다 505 시드에서도 낫겠지만, 차이가 공격 dev에서보다 작을 것이다.

결과별 대응:
- 크래밍 회복 + 희생 없음 → 종류별 임계값을 기본 방식으로 채택하고 S04(생성기 확장)의 기준선으로 쓴다.
  KOTOX가 2%p에 못 미치면 그 개선은 생성기 확장에 맡긴다.
- 크래밍 회복 실패 → 임계값을 나누는 것으로는 정상·난독화를 못 가른다. benign 음성 예시를 넣은 탐지기를
  붙이는 단계로 간다(수정기는 지금 모델 유지).
- 크래밍은 회복했지만 다른 기법이 1%p 넘게 떨어짐 → 예산이 모자란 것. 예산 곡선(0.5·1·2%)을 보고
  리뷰에서 예산 자체를 다시 정한다.
- benign test가 1.5%를 넘음 → dev 1,835문장으로 종류별 선을 고르기에는 표본이 작다는 뜻. 결론을 보류하고
  benign dev를 늘리는 방법(코퍼스 평가 분할 원문 추가 등)을 리뷰에 올린다.

  쓴다. 모델 구조·후보 위치 규칙은 그대로.

  두고, 종류별 임계값을 적용해 결과를 다시 계산한다. 데이터 로딩·CER 계산은 S02 러너(`run_e11_...`)의
  함수를 재사용한다.
- 새로 쓰는 데이터: 공격 dev(코퍼스 평가 분할 + 우리 생성기, gen_seed 1234). 기법별 문장 수는 기법당 500개 ×
  강도 2. benign dev·test, 505 시드, KOTOX test는 S02와 같다.
- 바뀌지 않는 것: S02의 공통 임계값 계산 함수. 비교군으로 그대로 다시 계산한다.
