# 단계 s02-generator-dependence

## 이 단계의 목적
복원기가 자체 난독화 생성기(`kslab/obfuscate.py`)에 얼마나 묶여 있는지 잰다. 지금까지 학습과
평가(505 시드)가 같은 생성기에서 나와, 수치가 "우리 생성기를 뒤집는 능력"만 반영한다는 문제가
제기됐다(2026-10-13 논의). 새 방법은 시도하지 않고 측정만 한다.

- e11a: 평가 데이터 구축 — KOTOX 규칙 코드 해독, 가역성 분류, benign dev/test 분할.
- e11b: 기법군 하나를 빼고 학습하면 그 기법군 복원이 얼마나 남는가(유지율).
- e11c: 자체 생성기로만 학습한 모델이 남의 생성기(KOTOX)에 얼마나 통하는가.
- e11d: 완벽한 탐지기를 가정하면 얼마나 고치나 — 탐지기·수정기 분리의 값어치.

결과로 다음 단계를 가른다: 생성기 확장(KOTOX 규칙 이식)을 먼저 할지, 탐지기 분리를 먼저 볼지.
공통 규약: BiLSTM, 임계값은 benign dev(KOTOX 학습 분할 정상 문장)에서만 고르고 test에 고정,
모델 시드 3개, KOTOX는 학습에 넣지 않음, GPU 학습. 계획 확정: 2026-10-14 사용자 "GPU 코드
수정하고 일단 실험 돌려봐".

## 종합 해석
세 가지가 확인됐다.

1. **복원기는 생성기에 강하게 묶여 있다.** 기법군을 빼고 학습하면 그 기법군 복원이 0이 된다(e11b, 평균
   유지율 -3.5%). 자체 생성기로만 학습한 모델은 KOTOX에서 +0.35%p, 슬롯 가역 쌍에서도 +0.67%p(e11c,
   benign 1% 기준). 지금까지의 505 시드 수치는 '우리 생성기를 뒤집는 능력'으로 읽어야 한다는 문제 제기가
   숫자로 맞다.
2. **성능을 깎는 건 탐지가 아니라 benign 보호용 임계값이다.** 공격 문장에서 모든 예측을 적용하면 oracle과
   거의 같다(e11d). 합집합 모델은 임계값 하나를 모든 기법에 공유해서, 확신이 낮은 기법(받침 크래밍)은
   고칠 능력(+33%p)이 있는데도 1% 지점에서 +0.21%p로 잘린다. KOTOX에서도 abstention을 끄면 슬롯 가역
   쌍이 +0.67 → +2.07%p로 오른다.
3. **KOTOX 같은 외부 난독화의 3분의 2는 슬롯 복원기 범위 밖이다**(길이 변화·lexical·structural, e11a).
   슬롯 복원기만으로 외부 데이터 전체를 고치는 건 목표가 될 수 없다.

믿을 수 있는 것: 시드 3개에서 방향이 모두 같다(유지율 범위, KOTOX 시드 범위). 믿기 어려운 것: KOTOX
규칙별 수치(규칙 혼합), coda·assimilation 유지율(분모 ≈ 0), '탐지 손실 몫'의 이름(실제로는 임계값 비용).
benign dev는 KOTOX 댓글체라 실제 대화형 benign 분포와 다르다.

## 다음 단계 제안
사전 결정 규칙(e11b 유지율 < 50%)은 '생성기 확장 우선'을 가리킨다. 다만 e11d가 그보다 싼 병목을
드러냈으므로 둘을 묶는 안을 제안한다. 리뷰에서 고른다.

- **안 A — 보정 먼저(학습 없음, 수십 분)**: s02 체크포인트 그대로, 예측 편집 종류·슬롯별 임계값을 benign
  dev에서 따로 골라 505 시드·KOTOX test 재평가. 받침 크래밍이 단일 모델 수준(+12%p)까지 돌아오는지,
  KOTOX 슬롯 가역 쌍이 2%p를 넘는지 본다.
- **안 B — 생성기 확장**: KOTOX slot 규칙(특히 우리에게 없는 1-4·2-1·2-2·2-3·5-2)을 `kslab/obfuscate.py`에
  이식하고 무작위화. 평가는 KOTOX 규칙 단위 홀드아웃(이식한 규칙 일부를 학습에서 빼고 KOTOX에서 측정)으로
  해야 '남의 생성기' 검증이 유지된다.
- 제안 순서: A → B. A가 B의 평가 기준선(임계값 방식)을 정하므로 먼저 하는 게 낫다.
- 버린 선택지: lexical·structural 규칙을 슬롯 복원기로 다루는 것(범위 밖, 별도 모듈 필요).
