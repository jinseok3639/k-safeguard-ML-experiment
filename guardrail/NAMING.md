# 실험 이름 규칙 — 가드레일 트랙

실험 이름이 문서·코드·결과 경로마다 달라지면 "이 수치가 어느 실행에서 나왔나"를 되짚을 수 없다.
이 문서는 사람이 이름을 지을 때 지킬 규칙만 적는다. id에 허용되는 글자, 결과가 쌓이는 폴더처럼
코드가 정하는 것은 `kslab/notes.py`·`kslab/tracks.py`가 원본이다.

이미 붙은 id는 이 규칙과 달라도 **바꾸지 않는다.** 어긋난 이름과 그 대응은 [`INDEX.md`](./INDEX.md)에 적는다.

## 세 층

| 층 | 무엇 | 예 |
|---|---|---|
| 작업 | 로드맵의 큰 일 하나. 여러 단계를 품는다 | P02 가드레일 다중, P03 LLM 강건성 |
| 단계 | 질문 하나. 리뷰를 받는 단위 | `p02-obf-robustness` |
| run | 실행 한 번. 결과 폴더 하나 | `p02.3-horizon-large` |

## 단계 id

- 형식: `p<작업 번호 두 자리>-<주제>`. 예: `p02-adaptive-attack`, `p03-refusal-bypass`.
- 한 작업에 단계가 여럿이면 주제로 구분한다. 번호나 날짜를 덧붙이지 않는다.
- 주제는 영어 소문자·숫자·하이픈, 두세 단어. 질문의 대상이 드러나게 쓴다(`obf-robustness`, `llm-understanding`).
- 2기 이전에 연 단계(`s01-…`, `s02-…`)는 그대로 둔다. 새 단계에 `s` 접두어를 쓰지 않는다 — 복원기 트랙의
  S01~S03과 겹친다.

## run id

- 형식: `p<작업 번호>.<순번>-<대상>`. 예: `p02.1-kanana`, `p03.2-kanana15-8b`.
- 순번은 **작업 안에서** 1부터 이어 붙인다. 단계가 바뀌어도 앞 단계에서 쓴 번호를 다시 쓰지 않는다.
- 대상은 그 run만 다른 것, 대개 모델이다. 모델은 계열·버전·크기·양자화 순으로 줄인다:
  `kanana`, `horizon-base`, `exaone4-32b-awq`, `kanana15-8b`. 한 번 정한 줄임말은 다른 단계에서도 같게 쓴다.
- **같은 설정을 다시 돌리거나 방식만 바꾼 변형**은 순번 뒤에 글자를 붙인다: `p02.5b-gemma4-e2b-logit`.
  새 질문을 묻는 run이면 새 순번을 쓴다.
- 실패한 run을 다시 돌릴 때는 새 id(글자 접미어)를 쓰고, 실패한 id는 대장에 남긴다.
- 모델 이름 대신 판정자·데이터 등을 바꾸는 run이면 바뀐 것을 대상 자리에 쓴다(`p03.4-judge-qwen3-32b`).
- `smoke`·`trial`·`scratch`가 들어간 id는 파이프라인 점검용이다. 결론을 내는 실행에 쓰지 않는다.

## 보이는 이름

- 대장·보고서에서 run을 부를 때는 `P02.3 Horizon large`처럼 **run id의 번호를 그대로** 대문자로 쓴다.
  보고서마다 따로 번호를 매기지 않는다.
- 다른 트랙과 함께 말할 때는 트랙을 붙인다: "가드레일 S01", "복원기 S01".
- 보이는 이름(제목)은 언제든 바꿔도 된다. id는 바꾸지 않는다.

## 파일 이름

| 파일 | 형식 | 예 |
|---|---|---|
| 보고서 | `reports/<단계 코드>_<주제 대문자>.md`. 단계 하나에 하나 | `reports/P02_ADAPTIVE_ATTACK.md` |
| 기준값 | `baselines/<run 또는 단계 접두어>_<대상>_v<판>.json` | `baselines/p02_kanana_v1.json` |
| 러너 | `exp/run_<단계 코드 소문자>_<주제>.py` | `exp/run_p02_adaptive_attack.py` |
| 결과 | run id 하나에 폴더 하나. 폴더 이름은 run id 그대로 | `p02.1-kanana/` |

- 기준값은 덮어쓰지 않는다. 같은 대상을 다시 집계하면 판(`v2`)을 올린다.
- 단계 하나의 스크립트가 여럿이면 `exp/<단계 코드 소문자>/` 아래에 모은다. 작업 번호만으로 폴더를 만들지 않는다.
- Colab 등 저장소 밖에서 돌린 결과도 run id 폴더 단위로 둔다. 여러 run을 한 폴더에 섞지 않는다.

## 상태 값

대장의 상태 칸은 복원기 트랙과 같은 값을 쓴다: `PROVISIONAL_DEV_ONLY`(리뷰 전 잠정) · `PROMOTE_CANDIDATE`
(기준 통과) · `DO_NOT_PROMOTE`(기준 미달, 기록용) · `중단`(결과 없음, 사유를 핵심 수치 칸에).
